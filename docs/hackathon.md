## Rules that can disqualify

Quoted from the guidebook, page 22 to 23:

> No code written before the event.

> You must submit a link to your source. All code outside of open source libraries must be written at the event. If you use any code written specifically for this idea in advance, or work on a new project that is somehow related to an already existing company, you will be disqualified. All project submissions are licensed under the MIT open-source license, and organizers must be able to access your source code.

Also:

- Team size: 1 to 4.
- At least one challenge. A project may be submitted to several challenges, and tech challenges run alongside any track.
- The pitch video is 2 minutes at most, enforced strictly.
- The team keeps ownership of its work; partner APIs and material stay under the partners' terms.

## What the final submission needs

- Project name, punchline, description
- Challenge(s)
- Technologies used
- A pitch video of **2 minutes maximum**, on a public platform (YouTube, Vimeo)
- Demo link and source code link
- Source code publicity setting
- Whether the team wants to be credited
- Pitch deck (PDF)
- Phone numbers of the team members, and a Discord username

For this challenge the demo link is the public URL on Hostinger.

## How it is judged

**Hostinger challenge** (the partner picks its own winners):

| Criterion | Weight |
| --- | --- |
| Detection quality: accuracy, false-positive handling, explainability | 40% |
| Technical execution and live deployment on Hostinger | 25% |
| Originality and real-world impact | 20% |
| Demo clarity | 15% |

Prizes: 2,000 €, 1,000 €, 500 €, plus a year of hosting and a domain for the three winning teams.

**Main prize** (10,000 €): peer review picks the top 5, who pitch for 3 minutes each with 3 minutes of questions; a jury of seven decides. Criteria: innovation, impact, implementation.

**Tech challenges**: each partner judges the best use of its technology. See `tech-challenges/`.
